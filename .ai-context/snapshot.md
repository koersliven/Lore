## Project Overview

**Lore** — 管理代码中的 WHY。让隐性知识随代码一起传承的开源框架。
核心思想：知识通过 git 传播，和代码享受同等待遇。
关键机制：知识自增长 + 模块化分区 + 设计意图层。

## Architecture

| 层 | 名称 | 内容 | 来源 |

## Key Decisions

### 模块化知识分区（2026-04-29）
- 单一 snapshot.md 是瓶颈：200 行限制、扁平加载、无领域分区
- 方案：保留全局 snapshot 向后兼容，新增 modules/ 按领域分区
- 零干预：代码结构=模块定义，affected_files=知识归类，猜错了后续自动修正
- L2 约束不拆分：约束天然跨模块，拆分会碎片化

### L0 prescriptive 设计层（2026-04-29）
- L3 记录"发生了什么"，L0 记录"应该怎么做"
- Spec 类型：api-design、data-model、flow-design、interface-contract
- 生命周期：draft → proposed → approved → implemented → superseded

### buffer flush 阈值基于知识条目数（2026-04-23）
- 按条目数更直接反映知识积累的实质
- soft=5, compact=8, hard=15

### 快照禁止直接编辑（2026-04-23）
- 只允许通过 /lore-evolve 编译产生
- 保护范围扩展到 modules/*/knowledge.md

## Constraints

- stop-flush.sh 和 config.yaml 中的阈值必须保持一致
- hook 脚本中 [LOCKED:] 标记防止 commit flush 和 stop flush 重复触发
