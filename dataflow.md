# AI Context 数据流 — 为什么这个架构有效

> 用一张图讲清楚：知识从哪来、到哪去、为什么比现有方案好。

---

## 一、问题：当前 AI coding 的知识流失

```
┌──────────────────────────────────────────────────────────────┐
│                     当前状态（知识流失）                        │
│                                                              │
│   开发者脑中知识                                              │
│   "这个接口不能改，因为..."                                    │
│         │                                                    │
│         │ 对话中说出                                          │
│         ▼                                                    │
│   ┌─────────────┐                                            │
│   │ AI 听到了    │ ← 对话窗口中有这些信息                       │
│   └──────┬──────┘                                            │
│          │                                                    │
│          │ 执行代码修改                                        │
│          ▼                                                    │
│   ┌─────────────┐                                            │
│   │ 代码 diff    │ ← 只有 HOW，没有 WHY                        │
│   └──────┬──────┘                                            │
│          │                                                    │
│          │ git commit                                         │
│          ▼                                                    │
│   ┌─────────────┐                                            │
│   │ commit msg   │ ← "调整超时配置" — 只说了做了什么             │
│   └──────┬──────┘                                            │
│          │                                                    │
│          │ 对话关闭                                           │
│          ▼                                                    │
│   ┌─────────────┐                                            │
│   │ 💀 知识死了   │ ← "为什么改"、"不能改什么"全部消失             │
│   └─────────────┘                                            │
│                                                              │
│   下次开发：一切从零开始                                        │
└──────────────────────────────────────────────────────────────┘
```

## 二、解法：AI Context 知识保留流

```
┌──────────────────────────────────────────────────────────────┐
│                   AI Context（知识保留）                        │
│                                                              │
│   开发者脑中知识                                              │
│   "这个接口不能改，因为..."                                    │
│         │                                                    │
│         │ 对话中说出                                          │
│         ▼                                                    │
│   ┌──────────────┐                                           │
│   │ Agent 识别   │ ← 自动检测知识信号（DECISION/CONSTRAINT）    │
│   └──────┬───────┘                                           │
│          │                                                    │
│          ▼                                                    │
│   ┌──────────────┐                                           │
│   │ .ai-context/ │                                           │
│   │              │                                           │
│   │ buffer.md    │ ← 实时缓冲，对话中持续写入                     │
│   └──────┬───────┘                                           │
│          │ 用户暂停 / commit 时触发                            │
│          ▼                                                    │
│   ┌──────────────┐                                           │
│   │ /digest      │ ← 整理为结构化增量文件                       │
│   └──────┬───────┘                                           │
│          │                                                    │
│          ▼                                                    │
│   ┌──────────────────────────────┐                           │
│   │ increments/                  │                           │
│   │  2026-04-23_buffer-tuning.md │ ← 版本化知识，随代码一起提交  │
│   └──────────────┬───────────────┘                           │
│                    │                                          │
│                    │ git push                                 │
│                    ▼                                          │
│   ┌──────────────────────────────┐                           │
│   │ 远程仓库（知识传播）            │                           │
│   │                              │                           │
│   │ 同事 clone → 继承全部知识       │                           │
│   │ 新 AI 工具 → 读 snapshot 入场   │                           │
│   └──────────────────────────────┘                           │
└──────────────────────────────────────────────────────────────┘
```

**关键区别：知识不再是"对话的副产品"，而是"开发的一等产物"。**

## 三、飞轮：为什么越用越强

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│   ┌─────────────┐                                          │
│   │  第 1 次迭代  │                                         │
│   │             │                                          │
│   │ Agent 理解度  │ ████████░░░░░░░░  30%                    │
│   │             │                                          │
│   │ 知识增量:    │ +2 decisions, +1 constraint              │
│   └──────┬──────┘                                          │
│          │                                                  │
│          │ 每次迭代都在积累                                   │
│          ▼                                                  │
│   ┌─────────────┐                                          │
│   │  第 10 次迭代  │                                        │
│   │             │                                          │
│   │ Agent 理解度  │ ██████████████░░  65%                   │
│   │             │                                          │
│   │ 知识增量:    │ +15 decisions, +8 constraints            │
│   │             │ +5 architectures, +3 externals            │
│   └──────┬──────┘                                          │
│          │                                                  │
│          │ 每次迭代都在积累                                   │
│          ▼                                                  │
│   ┌─────────────┐                                          │
│   │  第 50 次迭代  │                                        │
│   │             │                                          │
│   │ Agent 理解度  │ ██████████████████  85%                 │
│   │             │                                          │
│   │ 知识总量:    │ 60+ 条结构化知识                          │
│   │             │ 覆盖所有核心流程和约束                      │
│   └──────┬──────┘                                          │
│          │                                                  │
│          ▼                                                  │
│   Agent 不再需要"探索项目"                                   │
│   它读 snapshot → 理解上下文 → 直接给出正确建议                 │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**核心指标不是"AI 第一次理解项目多快"，而是"第 50 次迭代时，AI 对项目的理解远超第 1 次"。**

## 四、知识传播：一个人的积累，全团队的收益

```
┌──────────────────────────────────────────────────────────────┐
│                                                              │
│  开发者 A（北京）                    开发者 B（杭州）          │
│  ┌──────────────┐                   ┌──────────────┐        │
│  │ 与 agent 对话  │                   │ git pull      │        │
│  │ 积累项目知识   │ ── git push ──→  │ 获得 A 的积累  │        │
│  │ .ai-context/  │                   │ 站在 A 肩上   │        │
│  └──────────────┘                   └──────────────┘        │
│                                                              │
│  开发者 C（新入职）                  开发者 D（外包）          │
│  ┌──────────────┐                   ┌──────────────┐        │
│  │ git clone     │                   │ git pull      │        │
│  │ 获得 A+B 积累  │ ──────────────→  │ 获得 A+B+C    │        │
│  │ 第 1 天就懂    │                   │ 持续受益      │        │
│  └──────────────┘                   └──────────────┘        │
│                                                              │
│  AI Agent（任何工具）                                          │
│  ┌──────────────┐                                           │
│  │ 读 snapshot  │ ← 不需要 30 分钟探索，10 秒入场              │

│  └──────────────┘                                           │
│                                                              │
```

## 五、与现有方案对比：为什么它们是"一次性"的

```
┌──────────────────────────────────────────────────────────────┐
│                    现有方案（一次性）                           │
│                                                              │
│  CLAUDE.md / .cursorrules                                   │
│  ┌─────────────────────────────┐                             │
│  │ 人花 1 小时手写               │                             │
│  │ 写好后放在那里                 │                             │
│  │ 项目变了，文档没变 → 过期       │                             │
│  │ 新成员来了，不知道要更新它      │                             │
│  └─────────────────────────────┘                             │
│                                                              │
│  Hermes Agent（本地进化）                                     │
│  ┌─────────────────────────────┐                             │
│  │ agent 在使用中进化            │                             │
│  │ 但进化结果存在本地             │                             │
│  │ 同事看不到，换台电脑就没了      │                             │
│  └─────────────────────────────┘                             │
│                                                              │
│  问题核心：                                                    │
│  → 知识的生命周期 ≠ 代码的生命周                                │
│  → 知识不能随代码传播                                           │
│  → 知识不能自动更新                                             │
│                                                              │
└──────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────┐
│                    AI Context（持续增长）                       │
│                                                              │
│  .ai-context/                                                │
│  ┌─────────────────────────────┐                             │
│  │ 知识 = 一等公民               │                             │
│  │ 和代码一起版本化               │                             │
│  │ 和代码一起 review              │                             │
│  │ 和代码一起 push/pull           │                             │
│  │ 和代码一起回滚                 │                             │
│  └─────────────────────────────┘                             │
│                                                              │
│  知识的生命周期 = 代码的生命周期                                │
│  → 知识随代码传播（git clone 就继承）                           │
│  → 知识自动更新（每次开发产生增量）                              │
│  → 知识可追溯（increments 是完整历史）                          │
│  → 知识可审查（团队 review 知识变更）                           │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

## 六、架构优越性总结

```
┌────────────────────────────────────────────────────────────┐
│                                                            │
│  1. 知识是"长"出来的，不是"写"出来的                           │
│     ── 不需要人专门维护文档，正常开发就在积累知识                │
│                                                            │
│  2. 一个人的经验，全团队的资产                                  │
│     ── 通过 git 传播，不属于任何一个人                         │
│                                                            │
│  3. 越用越强，不是越用越累                                    │
│     ── 每次迭代增加理解，不需要额外维护                        │
│                                                            │
│  4. 快照是"编译"出来的，不是"编辑"出来的                       │
│     ── 保证质量一致性，源头是原始对话，不是人脑回忆              │
│                                                            │
│  5. 和代码享受同等待遇                                       │
│     ── 版本化、可 review、可回滚、可协作                       │
│     ── 这不是"又一个文档规范"，这是知识的版本管理系统             │
│                                                            │
│  6. 多道安全网防丢失                                         │
│     ── buffer 阈值触发 + commit 提取 + session 紧急 flush     │
│     ── 知识不会因为你忘了保存就消失                            │
│                                                            │
└────────────────────────────────────────────────────────────┘
```
